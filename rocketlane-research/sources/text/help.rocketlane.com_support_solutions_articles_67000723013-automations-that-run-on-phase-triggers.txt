Phase triggers monitor events that happen within phases, such as start date changes, due date changes, status updates, and phase deletion. You can use these triggers to automate follow-up actions when important phase-level changes occur.
Phase triggers can be configured at the template level for projects that use specific templates , or globally for all phases across projects.
In this article

Phase status updated

Phase deleted

Start date and due date updated
The Start date updated and Due date updated triggers run when a phase start date or due date changes.
You can use these triggers to notify stakeholders when a key phase timeline changes.
For example, when the start date or due date of the Go-live phase is postponed by 3 days, you can notify the project owner.

Phase status updated
The Phase status updated trigger runs when the status of a phase changes.
You can use this trigger to update project-level fields or notify teams when a phase reaches a specific status.
For example, when the Implementation phase is marked complete, you can update the project status to Implementation completed .

Phase deleted
The Phase deleted trigger runs when a phase is deleted from a project.
You can use this trigger to notify relevant stakeholders when a phase is removed.
For example, when a phase is deleted, you can notify the project owner and BU head in Slack.
